# Integration and ML/core review — 20 November 2026

## Existing changes understood and retained

The uncommitted work after `b913a15` changed the project substantially: organic
3D remove/grow/exchange actions replaced the active linked-floor copying decoder;
a factored coarse 2D+1D encoder mixed vertical context efficiently; coarse-to-fine
and multiscale experiments, taller context-derived envelopes, field/shadow/cache
optimizations, dense physical credit shaping, a live research dashboard and a
greedy height-graded core-placement prototype were added. Core observations raised
the active input count to 14. Legacy copying/tests remain compatibility controls.

The other agent's raw experiments and changes are preserved. The pasted response
reported an 80-episode Eixample spacing/distance A/B and proposed further
multi-objective/parallel methods. Its “converging” language exceeded the evidence:
one short site's increasing score or best episode does not establish convergence,
and changing the distance threshold changes the evaluated objective. Some original
weights are referenced only by private scratch paths and are not distributed.

## Compact plans implemented first

The old templates reserved 30/48/72/108/160 m² and included a lift even at 1–5F.
Those assumptions were replaced by the [canonical component plans](CORE_LAYOUTS.md):

| Floors | Stairs | Lifts | Metric area | One-metre reservation |
|---|---:|---:|---:|---:|
| 1–5 | 1 | 0 | 13.83 m² | 15 m² |
| 6–10 | 1 | 1 | 24.21 m² | 25 m² |
| 11–18 | 1 | 2 | 34.58 m² | 35 m² |
| 19–30 | 2 | 3 | 58.79 m² | 60 m² |
| 31–60 | 2 | 4 | 69.16 m² | 70 m² |

Each staircase has two landings/two flights; 18 risers span the 3 m storey. Lifts
show a separate shaft and car; lobby/opening geometry and dimensions are explicit.
The 10-storey case is now 5×5 m reserved, rather than the previous 6×8 m. Lift counts
are configurable task assumptions, not a universal architectural height rule.
The canonical source generates placement templates, API data and five SVG exports.
The main project remains ML research; the separate plan page inspects task geometry.

Walking distance also needed correction. The prior eight-neighbour sweep could
cut through blocked orthogonal corners and stopped after at most 64 iterations.
The new default converges and forbids corner cutting; independent Dijkstra tests
cover random grids and a winding route longer than 64 m. Explicit bounded screening
is still available for candidate placement. Distances remain to core footprints,
not modeled doors/corridors. Heights above 60 are outside the template schedule.

## Training correctness fixes

1. `UnifiedLearner.record` inherited a legacy list write to key `3`, while organic
   transitions stored/read `reward`. Intermediate rewards were therefore not used
   by the organic return calculation. Terminal `add_reward` did reach its correct
   field, so the prior runs were not entirely reward-free. The new override writes
   the actual step reward and has a regression test.
2. Organic training kept only the accepted Gaussian retry. The corrected score
   includes all consumed retries, including rejected draws, over the full latent
   grid. Spatial eligibility masking of log probabilities was removed because
   smoothing can cross eligibility boundaries.
3. Physical dense credit shaping is now named/configured as a heuristic auxiliary
   objective, not an exact control variate. The reference research config sets its
   weight to zero; the matched auxiliary config uses 1.2. UI behaviour retains its
   explicit auxiliary default.
4. Rollout batching groups by complete observation shape, so different XY grids
   can share a rollout without invalid stacking.
5. Live/headless reward definitions are shared in `voxelform/objectives.py`.
   Research evaluation records its decoding distribution; its matched defaults
   differ explicitly from the more concentrated UI inference settings.

These changes version the scientific protocol. Old numbers cannot be presented
as experiments of the corrected compact-core learner.

## ML project infrastructure

- Installable package and headless train/evaluate CLI, Python compatibility range,
  locked environment (`pyproject.toml`, `uv.lock`) and tested wheel/source build.
- Strict JSON configs, disjoint sites/model/evaluation seeds, city-separated real
  example splits and context-circle overlap checks where georeferencing exists.
- Untrained controls, fixed-budget final checkpoints, untouched test selection,
  retained failures, component metrics and a common post-episode core referee.
- JSONL trajectories; config/source/data fingerprints, dirty-source archives,
  dependencies/backend/hardware metadata and separate setup timings.
- Atomic policy/optimizer/RNG checkpoints with episode-boundary exact resume
  validation. Changed source, config, data or core semantics rejects exact resume.
- Summaries aggregate independent model seeds; repeated evaluation draws are not
  passed off as independent training runs. Uncertainty caveats are explicit.
- CPU GitHub Actions workflow, JS checks, static checks and a synthetic smoke run
  that requires neither the external urban cache nor the shared renderer.
- [Protocol](EXPERIMENT_PROTOCOL.md), [model card](MODEL_CARD.md),
  [data card](DATA_CARD.md), contribution rules and citation metadata.

No arbitrary code license was invented; that remains an owner decision. Private
weights, virtual environments, run directories and external cache stay out of Git.

## Limits and next work

This is a reproducible research foundation, not a completed Master's/PhD study.
The new full multi-seed real-site experiment has not been run to convergence.
More seeds/budgets, reward/decoder ablations, independent physical calibration,
statistical comparisons and reproduced alternatives remain substantive research.
The 80-episode historical A/B is useful exploratory evidence but not a substitute.
Preference conditioning, multi-head critics, PCGrad, Lagrange methods and parallel
speedups remain proposals rather than completed/verified contributions.
